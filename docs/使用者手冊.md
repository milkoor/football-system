# 足球数据分析系统 — 使用者手冊

**版本**: 1.2.0
**更新日期**: 2026-05-24

---

## 1. 系統簡介

本系統是一套一站式足球數據採集→量化分析→決策信號生成平台。爬取 titan007 公開賽程與盤口數據，計算 X 值，執行 ETL 分析並產出決策報表。

### 系統架構

```
┌────────────────────────────────────────────────────────────┐
│ 系統 A (FastAPI + PostgreSQL :8000)                        │
│  數據層：爬蟲 → 標準化 → 資料庫 → REST API                │
│  負責：聯賽爬取、賽程同步、盤口數據、結算計算              │
└──────────────────────────┬─────────────────────────────────┘
                           │ REST API
┌──────────────────────────▼─────────────────────────────────┐
│ 系統 B (Streamlit + SQLite :8501)                          │
│  分析層：關注管理 → X值計算 → ETL → 報表                  │
│  負責：數據同步、量化分析、分組管理、信號生成              │
└────────────────────────────────────────────────────────────┘
```

## 3. 標準工作流程

### 3.1 首次使用流程

```
系統同步 → 關注聯賽/賽季 → 完整同步 → ETL 執行 → 報表看板
```

### 3.2 詳細操作步驟

#### 步驟 1：系統同步

進入 **🔄 系統同步** 頁面：
1. 確認系統 A 連線狀態顯示「已連線」
2. 點擊 **「一鍵同步全部聯賽/賽季」**（約 14 秒完成）
3. 同步完成後可查看聯賽統計和賽季統計

#### 步驟 2：關注聯賽與賽季

進入 **📥 数据导入** 頁面：
1. 在「新增關注」區域選擇洲別 → 聯賽 → 賽季
2. 點擊 **「新增關注」**
3. 重複以上步驟添加所有需要分析的聯賽
4. 關注列表中會顯示已關注的聯賽/賽季

#### 步驟 3：完整同步

在 **📥 数据导入** 頁面：
1. 勾選需要同步的聯賽
2. 點擊 **「完整同步（賽程+賠率+X值）」**
3. 系統自動執行三步驟：
   - 賽程爬取（爬取比賽列表）
   - 賠率爬取（爬取每場比賽的盤口變動）
   - X 值計算（基於早盤→即時盤的波動計算）
4. 進度條顯示同步進度，完成後顯示摘要

#### 步驟 3b：僅導入到系統 B（跳過爬蟲）

如果系統 A 已有比賽數據（已爬取過），可直接導入系統 B：
1. 勾選需要導入的聯賽
2. 點擊 **「僅導入到系統B」**
3. 系統直接從系統 A 讀取數據、計算 X 值、寫入本地 SQLite

#### 步驟 4：快速配置分組

進入 **▶️ ETL執行** 頁面：
1. 確認「全域分組」已建立（Top / Mid / Weak）
2. 若聯賽尚未配置隊伍分組，點擊 **「⚡ 快速配置（自動建立分組並分配全部隊伍）」**
3. 系統會自動從系統 A 獲取該聯賽所有隊伍，均分到各分組
4. 也可進入 **👥 队伍分组** 頁面手動編輯分組隊伍

#### 步驟 5：執行 ETL

在 **▶️ ETL執行** 頁面：
1. 勾選需要執行的聯賽
2. 可展開「🔧 進階：自訂賽季配對」指定 current/previous 賽季
3. 點擊 **「▶️ 執行 ETL」**
4. 進度條顯示處理進度
5. 完成後顯示結果摘要與品質問題

#### 步驟 6：檢視報表

進入 **📊 报表看板** 頁面：
1. 選擇 ETL 版本（Run ID）
2. 按洲別分頁檢視
3. 每個聯賽顯示五大區間（Z1~Z5）的信號
4. 展開可查看詳細數據：上季贏/輸、當季贏/輸、總贏/輸、護級、強度、信號
5. 可按分組（Top/Mid/Weak）、玩法（HDP/OU）、時段（Early/RT）篩選
6. 可匯出 Excel 報表

## 4. 功能頁面說明

系統 B 提供以下功能頁面，從左側選單進入：

### 4.1 🏠 首页

系統概覽頁面，顯示：
- 平台功能簡介
- 快速入門指引
- 活躍聯賽數、總比賽數等即時指標
- 系統 A 連線狀態

### 4.2 🔄 系統同步

管理系統 A 到系統 B 的數據同步（聯賽/賽季標籤）。

**功能：**
- 系統 A 連線狀態監控
- 一鍵同步全部聯賽和賽季標籤（batch-sync-seasons）
- 同步統計查看
- 手動清除本地數據

### 4.3 📥 数据导入

核心數據導入頁面，管理關注聯賽並執行數據同步。

**功能：**
- **關注聯賽管理**：新增/移除關注的聯賽和賽季
- **完整同步**：賽程爬取 → 賠率爬取 → X 值計算（三步自動化）
- **僅導入系統 B**：跳過爬蟲階段，直接從系統 A 讀取數據寫入本地 SQLite
- **同步進度顯示**：即時進度條和摘要報告
- **匯入歷史紀錄**：查看每次導入的詳細結果

### 4.4 ▶️ ETL執行

手動執行 ETL 數據分析管線。

**功能：**
- **聯賽選擇**：按洲別篩選，勾選需要執行的聯賽
- **快速配置分組**：自動建立分組並從系統 A 獲取隊伍均分
- **自訂賽季配對**：可手動指定 current/previous 賽季（非預設配對）
- **執行 ETL**：一鍵執行完整分析管線
- **最近執行紀錄**：快速查看最近的 ETL 結果

**前置條件：**
- 必須先建立全域分組（Top/Mid/Weak）
- 每個聯賽至少有一個分組配置了隊伍
- 已導入比賽數據（match_records）

### 4.5 📊 报表看板

檢視 ETL 執行後的決策信號結果。

**功能：**
- **ETL 版本選擇**：切換不同 Run ID 的結果
- **洲別分頁**：AFR / AME / ASI / EUR
- **分組頁籤**：Top / Mid / Weak 各自獨立顯示
- **玩法/時段篩選**：HDP（讓球）/ OU（大小）、Early（早盤）/ RT（即時）
- **信號視覺化**：顏色標記的信號強度
- **詳細數據**：展開可查看上季贏/輸、當季贏/輸、總贏/輸、護級、強度
- **Excel 匯出**：匯出當前篩選條件的報表

**信號說明：**

| 信號格式 | 含義 |
|----------|------|
| `A2` | A 方向，強度 2 |
| `B0.5` | B 方向，強度 0.5 |
| `A4` | A 方向，強度 4（護級升級後） |
| （空白） | 無信號 |

### 4.6 📜 历史纪录

查看和管理 ETL 執行歷史。

**功能：**
- **執行列表**：顯示所有 ETL 執行的 ID、時間、狀態
- **檢視詳細**：查看執行參數快照、品質問題、決策結果
- **清理舊紀錄**：保留最近 N 筆，刪除舊紀錄

### 4.7 👥 队伍分组

**功能：**
- **全域分組管理**：新增/刪除分組（Top / Mid / Weak）
- **隊伍分配**：每個聯賽 × 每個分組可獨立配置隊伍（current/previous）

- **不匹配檢測**：檢測並修復分組隊伍的不匹配問題

### 4.8 🏆 联赛管理

## 5. X 值計算說明

### 5.1 什麼是 X 值

X 值是衡量盤口賠率波動的量化指標，基於 AH（亞洲讓球）盤口的早盤到即時盤變化計算。

### 5.2 計算邏輯

1. 獲取比賽的 AH 盤口變動歷史
2. 篩選「早」區間的盤口數據
3. 比較最早與最晚的賠率：
   - 有紅色 `*` 標記：比較客隊 vs 主隊賠率（客低有利）
   - 無紅色 `*` 標記：比較主隊 vs 客隊賠率（主低有利）
4. 計算賠率變化差值作為 X 值
5. 若盤口無波動或不符合條件，標記為「不適合」

### 5.3 X 值區間分類

```
區間 1: X ≤ -0.24
區間 2: -0.24 < X ≤ -0.22
區間 3: -0.22 < X ≤ -0.15
區間 4: -0.15 < X ≤ -0.08
區間 5: -0.08 < X ≤ -0.03
區間 6: -0.03 < X ≤ +0.07
區間 7: +0.07 < X ≤ +0.15
區間 8: +0.15 < X ≤ +0.23
區間 9: X > +0.23
```

## 6. 常見問題

### Q: 系統 A 連線失敗？
A: 檢查 System A 容器是否運行：`docker-compose ps system_a`。確認 `system_a_api_url` 配置正確（預設 http://system_a:8000 或 http://localhost:8000）。

### Q: 同步後看不到聯賽？
A: 先執行「一鍵同步全部聯賽/賽季」（系統同步頁面），再到「数据导入」頁面新增關注。

### Q: ETL 執行時顯示「沒有已同步比賽紀錄的聯賽」？
A: 先在「数据导入」頁面執行「完整同步」或「僅導入到系統B」，確保有比賽數據寫入本地 SQLite。

### Q: 快速配置按鈕不出現？
A: 需先建立全域分組（Top/Mid/Weak）。到「队伍分组」頁面新增分組後再回到 ETL 頁面。

### Q: ETL 結果全為零？
A: 很可能缺少結算數據。到系統 A 執行批量結算：`curl -X POST "http://localhost:8000/api/matches/auto-settle?league_id=xxx&season=2025-2026"`，然後重新導入系統 B。

### Q: 如何重新執行 ETL？
A: 直接再次執行即可，每次執行會建立新的 `etl_run` 紀錄，不會覆蓋舊結果。可在報表看板中切換版本比較。

### Q: 資料庫檔案在哪裡？
A: 系統 B 的 SQLite 位於 `system_b/db/quant.db`。系統 A 使用 PostgreSQL，數據保存在 Docker volume 中。

### Q: 如何備份資料？
A: 系統 B 可在「数据库管理」頁面一鍵備份。系統 A 的 PostgreSQL 可使用 `docker exec football_system_a pg_dump -U postgres football`。

### Q: 日職聯（JLeague）數據不完整？
A: JLeague 的賽季標籤使用年份格式（如「2026」而非「2025-2026」）。如果同步有問題，請使用系統同步頁面的一鍵同步功能，系統會自動嘗試多種目錄格式查找 JS 檔案。

### 7.3 ETL 處理流程

```
比賽記錄（match_records）
    │
    ▼
X 值分類（9 個區間）
    │
    ▼
輪次區段匯總（每 10 輪一段，最多 6 段）
    │
    ▼
跨賽季合併（current + previous）
    │
    ▼
五大區間合併（9 → 5）
    │
    ▼
護級判定（0~3）→ 強度升級（2→4）→ 信號產生
    │
    ▼
品質檢查 → 結果存入 SQLite
```
